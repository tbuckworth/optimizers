Weight-Covariance Spectral Optimizer v2 — Experiment Results

Batch-mean streaming SVD (no per-sample gradients). Best config from sweep: rank=500, decay=0.99, warmup=100 steps. Compared vs Adam on three MNIST variants, 20 epochs each.

v2 vs v1: Switching from per-sample gradients (v1) to batch-mean streaming (v2) with higher rank dramatically improved results. On standard MNIST, ours now matches Adam (98.05% vs 97.98%). The generalization gap remains much smaller for ours. Random label memorization is still blocked. Speed improved from 21-36x to ~9x overhead.

Observations

Standard MNIST — ours matches Adam: Ours converges more slowly (94% at epoch 0 vs Adam's 97%) but catches up by epoch 14 and finishes at 98.05% vs 97.98%. The slower start is expected — the filter needs time to build a good covariance estimate. But once it has one, it learns just as well.
Noisy MNIST — nearly tied: Adam: 96.84%, Ours: 96.38%. Only 0.46% gap. Both handle the 784 extra noise features surprisingly well. Adam's test loss diverges more (0.26 vs 0.17), suggesting it's memorizing noise features more than ours, but the accuracy difference is small.
Random labels — still blocked: Our optimizer barely moves from chance (10.7% train, 9.2% test after 20 epochs). Loss stays near ln(10)=2.303. Adam slowly starts memorizing (14.7% train). With more epochs, Adam would continue memorizing while ours would stay flat.
Speed tradeoff: Ours is ~9x slower than Adam (322s vs 36s for 20 epochs standard MNIST). Most overhead is the GPU matmul for V@coeffs (235K x 500 per step). Acceptable for research; would need optimization for production.
