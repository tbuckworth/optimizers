Gradient Covariance Spectral Filtering

A gradient-filtering wrapper for neural network optimizers

1. Overview

We describe a gradient-filtering method that wraps any base optimizer (e.g. Adam). The method maintains a low-rank estimate of the covariance matrix of gradient updates across training steps. At each step, the current gradient is projected onto the top eigenspace of this running covariance before being passed to the base optimizer. The effect is that only gradient directions which recur persistently across many batches are retained; transient directions are discarded.

The method has a single forward/backward pass per step and uses batch-mean gradients (not per-sample gradients). The computational overhead comes from a rank-1 SVD update and a matrix-vector projection, both operating on a low-rank factored representation that never materialises the full p × p covariance matrix.

3. Method

3.1 Running Mean

The gradient stream is centred using an exponential moving average with the same decay factor λ used for the covariance:

μt = λ · μt−1 + (1 − λ) · gt

Initialised as μ1 = g1 (the first gradient). The centred gradient is:

g̃t = gt − μt

3.2 Streaming Rank-1 Covariance Update

We maintain the covariance in factored form. Conceptually, the running covariance at step t is:

Ct = λ · Ct−1 + (1 − λ) · g̃t g̃t⊤

We never form Ct explicitly. Instead, we store its top-k eigendecomposition as Vt (eigenvectors) and St (singular values, i.e. square roots of eigenvalues). Each step updates this factored representation as follows.

Define scaling constants sd = √λ and sn = √(1 − λ). Consider the (kt−1 + 1) × p matrix whose rows are the weighted basis vectors of the new covariance:

rows 1 … kt−1:   sd · St−1[i] · Vt−1[:, i]   for each i
row kt−1 + 1:   sn · g̃t

The covariance Ct equals this matrix's Gram matrix (i.e. rows⊤ · rows). Instead of forming the (kt−1 + 1) × p matrix, we compute its (kt−1 + 1) × (kt−1 + 1) inner-product matrix analytically:

G[i, j] = sd2 · S[i] · S[j] · δij   for i, j ≤ kt−1
G[i, kt−1+1] = G[kt−1+1, i] = sd · sn · S[i] · c[i]   where c = Vt−1⊤ g̃t
G[kt−1+1, kt−1+1] = sn2 · ‖g̃t‖2

This small matrix is eigendecomposed:

G = Q · diag(Λ) · Q⊤

where Λ are eigenvalues (descending) and Q are eigenvectors. We discard eigenvalues below 10−12 and keep at most k components. The new singular values are:

St = √Λ   (element-wise square root of kept eigenvalues)

The new eigenvectors are recovered without materialising any p-wide matrices beyond Vt−1 itself:

α = sd · diag(St−1) · Q[1:kt−1, :] · diag(1/St)   ∈ ℝkt−1 × kt
β = sn · Q[kt−1+1, :] · diag(1/St)   ∈ ℝkt

Vt = Vt−1 · α + g̃t · β⊤

Here g̃t · β⊤ is the outer product of the centred gradient (p × 1) with the coefficient vector (1 × kt), giving a p × kt contribution. The full Vt update is a weighted combination of the old basis and the new gradient direction. All arithmetic on the p-dimensional vectors is performed on GPU; only the small (k+1) × (k+1) eigendecomposition is performed on CPU.

Note on orthonormality. The columns of Vt are approximately orthonormal by construction (they are the top eigenvectors of the Gram matrix, which encodes the geometry of the combined basis). In practice, numerical drift is small and we do not re-orthogonalise.

3.3 Gradient Projection

After the warmup period (t > warmup), the gradient passed to the base optimizer is replaced by its projection onto the current eigenspace:

gtfiltered = Vt (Vt⊤ gt)

This retains only the component of the gradient lying in the span of the top kt eigenvectors of the running covariance. An optional filter\_strength ∈ [0, 1] parameter interpolates between the original and projected gradients:

gtfiltered = (1 − φ) · gt + φ · Vt (Vt⊤ gt)

In all experiments reported here, φ = 1 (full projection).

3.4 Warmup

During the first warmup steps, the covariance estimate is updated but the gradient is not filtered. This allows the eigenspace to accumulate enough signal before filtering begins. During warmup, training proceeds identically to the base optimizer.

Input: model fθ, base optimizer (e.g. Adam), rank k, decay λ, warmup w
State: V = None, S = None, μ = None, t = 0

for each mini-batch (x, y):
  1 t ← t + 1
  2 loss = L(fθ(x), y)    // standard forward pass
  3 gt = ∇θ loss       // standard backward pass (batch-mean gradient)
  4 flatten gt into a single vector ∈ ℝp

   // Update running covariance estimate
  5 μt = λ · μt−1 + (1 − λ) · gt   // or μ1 = g1 at first step
  6 g̃t = gt − μt
  7 update (V, S) with rank-1 observation g̃t // Section 3.2

   // Apply spectral filter (after warmup)
  8 if t > w:
    9 gt ← V (V⊤ gt)     // project onto top eigenspace
    10 write gt back into θ.grad

  11 base_optimizer.step()    // Adam (or any optimizer) uses the filtered gradient

4. Intuition

The gradient covariance matrix Ct captures which parameter-space directions receive consistent gradient signal across training steps. Its top eigenvectors span the subspace of directions that are pushed by many different mini-batches. Its bottom eigenvectors (or the null space) correspond to directions driven by individual batches or individual samples — the directions used for memorisation.

When training labels are correct, the true decision boundary produces gradients that align across batches, dominating the top eigenspace. When labels are corrupted, the corrupted examples produce idiosyncratic gradients that do not persist in the covariance spectrum. By projecting onto the top eigenspace, we retain the structured signal and discard the noise.

In the limiting case of fully random labels, no gradient direction is more persistent than any other — the covariance spectrum is flat. The projection retains an arbitrary k-dimensional slice, effectively destroying the gradient signal. The network cannot learn.

5. Computational Cost

Per training step, the additional operations beyond standard training are:

  1. Flatten gradient: O(p) — concatenate parameter gradients.
  2. Running mean update: O(p) — elementwise EMA.
  3. Compute c = V⊤ g̃: one matrix-vector product, O(pk).
  4. Build Gram matrix G: O(k2) — analytic construction from S, c, and ‖g̃‖2.
  5. Eigendecompose G: O(k3) — small matrix, done on CPU.
  6. Recover Vt: one (p × k) · (k × k') matmul plus one outer product update, O(pk').
  7. Project gradient: two matrix-vector products, O(pk).

Total additional cost per step is O(pk), dominated by the matrix-vector products with the p × k eigenvector matrix. For the experiments reported here (p = 235,146, k = 200), the overhead is approximately 2× wall-clock time compared to Adam alone.

Critically, the full p × p covariance matrix is never formed. The p × k factor V and the k-vector S are the only large data structures. Memory overhead is O(pk).

6. Hyperparameters

7. Diagnostics

The method exposes the following diagnostics at each step:

  • Singular value spectrum (St): The singular values of the running covariance, in descending order. A steep falloff indicates the gradient signal is concentrated in few directions; a flat spectrum indicates diffuse or random gradient structure.
  • Effective rank: The exponential of the Shannon entropy of the normalised squared singular values: exp(−∑ pi log pi) where pi = Si2 / ∑ Sj2. Ranges from 1 (all variance in one direction) to k (uniform). In experiments, effective rank typically lies between 30 and 85, well below the maximum rank of 200.
  • Variance in top-5: Fraction of total variance captured by the five largest singular values. Provides a quick summary of spectral concentration.

8. Implementation Details

  • All parameters of the network are concatenated into a single flat vector for the covariance computation. The ordering is determined by iterating model.parameters().
  • The gradient vector gt used for both the covariance update and the projection is the unfiltered batch-mean gradient from loss.backward(). The projection is applied after the covariance update, so the covariance always sees the true gradient.
  • The singular values S are stored on CPU (for compatibility with torch.linalg.eigh). The eigenvectors V and all p-dimensional operations remain on GPU.
  • Eigenvalues below 10−12 are discarded to avoid numerical instability in the eigenvector recovery (which divides by singular values).
  • The method wraps the training loop rather than subclassing torch.optim.Optimizer, because it needs access to inputs and targets for the forward pass. Its step(inputs, targets) method performs the full forward/backward/filter/update cycle.
