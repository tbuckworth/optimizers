# Next scope: authentic storage evidence and bounded outside-root writers

Codex / Spectral Optimizer Investigation, 7 September 2026. Read-only proposal
following the write-enforcement checkpoint. Not an implemented decoder, a
measurement already run, approval to run specimens, or native permission.

## Why the current gate stays closed

The current request binds an admission file, and that file pins a layout file,
but neither development nor later-phase permissions bind the admission pin.
The journal also does not preserve it. A request caller can substitute another
self-consistent self-report. Hashes authenticate bytes, not historical execution
or independent review. No production creator currently enforces the later
permission files' or either prerequisite evidence file's write limits.

## Smallest proposed implementation

Separate a Torch-free-at-import authority/writer module from the explicit CPU
serializer cross-check runner. Keep both default CLIs inert. Add both to the
scientific source manifest; implement/test/review all modules and shared edits
before freezing a clean revision C and exact source digest S.

The authority module strictly decodes duplicate-free canonical ASCII JSON for
the existing two <=64-KiB evidence files. It recomputes the current topology,
ledger, component membership and fixed conditions, not caller totals. The
measurement must have exactly the 11 ordered component kinds; each actual
serializer size must not exceed its analytic ceiling. Measured maxima and the
weighted measured sum remain diagnostic cross-checks, never premises replacing
the prospective bound. Fresh worker runtime checks still enforce actual source,
environment, RNG layout and pinned serializer configuration.

The cross-check runner is a future explicitly invoked, sequential CPU-only
serializer measurement. It should create unregistered nonsemantic storage
specimens, not scientific artifacts or native-layout observations. No IDX,
scientific plan, training, CUDA initialization or consumed-inspection retry.
Use one bounded in-memory serialization buffer at a time and retain only the
bounded report, including exact source/runtime bindings, all 11 rows, encoder
facts, analytic comparisons, observed resources and false authority flags.
The prior proposed 120-second/2-GiB/hidden-CUDA/four-single-thread scope must be
checked against the final assembled runner before execution, not assumed from
passing tiny unit tests. The mandatory real cross-check is not being dropped.

After actual execution, an independent review of exact measurement M produces
separate admission/review A. The runner cannot self-admit. Both are written
outside the frozen clean source checkout, at the two already charged fixed
paths. They bind C/S; any subsequent execution-source change invalidates them.
Do not hard-code M's hash into C: a commit cannot contain the hash of evidence
which itself claims to have measured that same commit.

Extend development and later permissions with the exact A pin. Bootstrap copies
it to the external/root journal. Later permission creation derives it from the
authenticated journal and prior sealed boundary; acquisition authenticates the
same chain. Each of four requests must match its permission's A pin and the
same journal-bound A/M/C/S. Existing marker permission pins need no duplicate
field. Supervisor authentication checks the chain before child launch where
possible; the worker rereads and validates it before root creation/reopen.

Evidence and later-permission creators pre-encode under their existing 64-KiB
and 8-KiB caps and use descriptor-relative, no-follow, direct-final `O_EXCL`
writes, private regular files, bounded writes, file/directory fsync and verified
final identity/hash. No temporary copies, rename, backup, retry or failure
sidecar is allowed by this accounting. A partial final file consumes its fixed
slot and remains within the pre-encoded cap; it blocks admission/acquisition.
Check complete expected namespaces and free-space floor. Preserve all partials.

The control-side reviewed exact-permission/pin channel is the trust anchor under
the existing workflow. Pin equality prevents later request substitution; it is
not cryptographic proof of measurement or protection against a caller able to
fabricate measurement, admission and the trusted permission itself. A stronger
adversarial claim would need a separate externally pinned reviewer signature,
which is neither required nor authorized by this proposal.

## Required unit contracts before any measurement

Test exact schemas/order/types/duplicate rejection; all 11 components and
analytic recomputation; pin substitution across all four phases; persistence in
the journal; changed revision/source rejection; enlarged request/permission
maximum encodings under unchanged 8-KiB caps; partial/short/exclusive writes and
zero simultaneous temporary copies; no overwrite/retry or self-admission.
These may use explicitly synthetic tiny CPU fixtures, not fabricated production
evidence. Then review the assembled final source/resource scope, freeze, and
only separately decide the real cross-check. No native GO is implied.
