# Native record engineering review

Codex / Spectral Optimizer Investigation. Dataset-free CPU and synthetic
contract checks only; no new scientific finding or native-pilot decision.

## Reviewed change

Two pure modules now separate schedule/declared-resource consistency from
source-state record construction and cross-record comparisons. The native
runner remains disabled. The parent implemented policy/tests/contract and
source membership integration; a bounded leaf implemented source-history
records/tests. Independent read-only leaves reviewed membership/design and
the resulting implementation. No reviewer was authorized to launch a study.

The design review identified18 retained anchor groups versus16 scientific
audits, the need for a separate counter-zero snapshot, retention of both pilot
final cores, exact operation ordering and one clean source checkout throughout
a future attempt. These are incorporated. The proposed alternative of charging
all scientific plan creation to development was not adopted: a development-only
permission must not silently expand to four scientific plans. The metadata
schedule charges explicitly authorized preparation to primary's unchanged
cumulative allowance before its separate GO. No preparation was executed.

## Reproduced defects and corrections

- Parent reproduction accepted a complete transcript declaring18,900 total
  root bytes while its own payload and receipt declarations totaled21,290.
  The missing cumulative lower-bound check was added; no actual-file verification
  is inferred. Standalone record validation now also rejects event/kind mismatch.
- Independent review reproduced acceptance of a changed sensitivity environment,
  normal usage consuming the1-MiB failure reserve, and a retained16,000-byte
  failure with only1,000 bytes of declared root growth. Regressions now require
  primary/sensitivity environment equality, preserve the normal-write reserve,
  and account for declared failure bytes. Failed observations may still retain
  actual overruns instead of clipping them to successful limits.
- Source-history fixed dictionaries initially used Python equality that could
  accept integer0 in place of false. Exact typed comparisons and bounded
  receipt metadata now reject that and string/container subclass substitutions.
- Independently valid capture records could initially disagree with one another.
  The bundle validator now links every on/off fingerprint, trajectory, plan and
  source/environment reference, then recomputes the final pair from both retained
  full cores. Earlier full-state bytes remain unavailable to later validation.
- The parent reproduced a supposedly initial observer with counter0 but a
  nonzero historical stabilization count. A dedicated constructor-state check
  now requires absent V/S/projection/gradient mean, exact zero counters and
  positive-zero maximum error. It does not weaken the existing state-core schema.
- Independent final review noted unbounded native RNG/device fields in the
  generic core schema. Source-history admission now bounds full-state data
  before validation/hash copies, including pending traversal nodes and hidden
  tensor backing storage. These representation ceilings are not native layout
  measurements or a process resource gate.

These corrections affect new engineering records, not the production optimizer,
numerical tolerances, prior raw studies or the delivered report. Hypothesis-first
debugging isolated consistent metadata counterexamples before changing checks.

## Evidence and limitations

The source-history tests run actual eight-update tiny CPU trajectories and
compare their complete supplied states. Their plan/anchor/witness references
are explicitly synthetic declarations, not on-disk scientific receipts.
Identical CPU trajectories test the codec; they do not test the neutrality of
actually sealing captures in one arm of a native pilot. Adverse component
differences and signed-zero changes remain observable in comparison records.

Review also demonstrated two genuine trust limitations. Lazy input iterators
can execute caller work, and model/optimizer hooks can be invisible or distort
state-dict snapshots. The streaming API is retained to avoid holding2,000 full
cores in memory; its documentation now explicitly disclaims side-effect
sandboxing and complete live-object equivalence. A regression demonstrates
that an installed forward hook is invisible to snapshot equality. The disabled
native adapter must establish hook-free live bindings and account for iterator
work; no present snapshot or digest proves execution history.

An in-memory serialization check measured28,833 bytes for a tiny on-completion,
27,873 for off-completion, and13,337 for primitive comparison JSON. The synthetic
90-record policy transcript occupied120,257 canonical JSON bytes in total,
with largest record4,816 bytes. No artifact files were written. These exact
synthetic metadata values are not full-width bounds or native resource results.
The configured96×128-KiB phase-record body ceiling is12MiB before receipts and
other metadata; it is not a claim that the complete study fits.

Native gate/input/proof binding, collector checks, mount/root inspection,
actual retained inventory, missing-probe/pre-root failure representation,
source history scheduling and native all-phase resource measurement remain
adapter work. In particular, full-state hashing/comparison overhead must be
measured, not omitted because only compact traces are retained. No hash-only
validator authenticates historical computation or a reviewed authorization.

Official API checks used Python JSON documentation and installed-version
PyTorch2.11 reproducibility guidance, linked in the contract. They support
parser and same-platform scope choices, not empirical conclusions.

Final commands, counts, source hashes and review status are recorded in
`native-records-checks.json`. Prior checkpoint records remain historical.

The final independent bounded-helper review found no blocking defect within
this documented scope;15 source-history and17 policy tests passed with CUDA
hidden. Expansion of one bounded dictionary can briefly allocate a traversal
stack below3× the node limit before rejecting excess pending nodes; this is
still a bounded representation check, not a claimed process-memory ceiling.
