## Scope and independent count

The previous fixed-field specimen explicitly omitted complete envelope
metadata. The new assessment uses actual current tiny producers and validators,
then separately constructs nonsemantic full-width storage values. The
current inventory (artifact not distributed in this public snapshot) independently recounts the
required tensors and the six final cores/five plans missing from the old
group-only projection. The old group arithmetic was correct; the parent's
new draft long-plan sum was not and was corrected before measurement.

The tiny fixture is not a scientific source trajectory. In particular its
source-history helper uses synthetic references, and its equal capture-on/off
histories do not exercise native capture neutrality. Original tiny validation
and lifted storage coverage must remain distinct claims.

## Measurement defects found before acceptance

Parent review formed and tested two specific failure hypotheses. On the first
implementation, a tensor at an unknown full path ending in `g.value` was
accepted by the suffix classifier. Separately, a patched restricted loader
changed a primitive string while the measurement still reported round-trip
success. Both minimal reproductions completed successfully (handle29325),
confirming measurement-code defects rather than optimizer behavior.

The initial aggregate also serialized the primitive pilot comparison with
Torch, although its retained contract specifies JSON. The corrected measurement
must use the strict JSON codec and count its actual bytes. CPU RNG shape
observation must not be mislabeled as observed native state: zero/one-filled
RNG values from the initial implementation were synthetic, not valid captured
RNG evidence.

The revised implementation rejects unexpected full tensor paths and dtypes,
compares complete ordered typed trees (including signed float bits), and uses
strict JSON for the comparison. Actual fixture CPU RNG leaves are now cloned
unchanged with explicit value-policy labels. Targeted regressions cover the
reported failures. These changes do not modify scientific validators or the
production optimizer.

Parent measurement after those fixes completed zero and one patterns in9.364
and8.510 seconds respectively (handle29215). Both give945,340,050 bytes, or
901.546526 MiB, for the fixed component projection. The initial945,253,978-byte
value is superseded because it used the wrong comparison encoding. Detailed
component bytes, serialized hashes and manifest hashes are retained in
full-storage-measurement.json (artifact not distributed in this public snapshot). Full manifests
are reproducible via the pinned measurement function; bulk specimen bytes were
not retained. This was an engineering measurement, not a scientific rerun.

The final helper now checks the exact92 audit-bitset paths and their required
set, alongside complete required tensor sets. Parent read-through and eight
focused tests pass after these edits (12.564 seconds, handle85795). Repeated
zero/one measurements take9.176 and8.318 seconds (handle84100), each projecting
945,341,202 bytes. See final measurement (artifact not distributed in this public snapshot)
for the exact source hashes and all component checks.

The final repeat is1,152 bytes larger than the earlier corrected projection:
64 extra bytes per anchor, with every tensor/bitset inventory and lift-manifest
hash unchanged. This is primitive/container overhead variation. The fixture
seeds Torch but preserves ambient Python/NumPy RNG state; Python RNG primitive
values can therefore differ between processes. A controlled three-value RNG
encoding diagnostic changed Python's protocol2 pickle length (3,797/3,809/3,821
bytes) but did not change the padded full-anchor archive size for those three
values. It does **not** prove the exact cause of the earlier64-byte difference.
Original bulk specimens were deliberately not retained, so a retrospective
byte-by-byte attribution is unavailable. This small variation is retained,
not removed by reporting only one favorable observation or called a bound.

## Interpretation boundary

Every expanded audit coordinate bitset is a constructed all-failure mask, not
an actual numerical failure. Scalar diagnostics and fixture provenance remain
tiny values. Even complete current field coverage is not a worst-case native
metadata bound; unknown adapter records cannot be silently absorbed by a
residual allowance. Each component is measured separately and multiplied by
fixed membership, not written as a full study.

The source-derived CUDA RNG length prediction in the inventory is not a device
observation. Native entry, actual full-root writer/receipts/control/failure
records, peak memory and all-phase timing remain separate requirements.
No 1-GiB fit certificate or native-pilot approval follows from this assessment.

The official serialization and JSON guidance informed storage ownership,
restricted loading and exact primitive checks; it does not establish empirical
resource feasibility. [PyTorch 2.11 serialization](https://docs.pytorch.org/docs/2.11/notes/serialization.html),
[Python 3.12 JSON](https://docs.python.org/3.12/library/json.html).
