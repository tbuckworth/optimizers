## Accepted control design

Keep ArtifactStore terminality absolute. Do not add post-terminal writes.
A retained policy failed record is evidence only when its ordinary create-only
write actually completed. Otherwise the existing store failure file and actual
verified policy prefix are sufficient terminal/incomplete evidence. Inspection
must not manufacture a missing failed record or resume an incomplete operation.
Uninspectable, malformed, store-terminal, declared-failed and unfinished roots
are all ineligible for native writable continuation.

The actual GO is an externally reviewed, exact launcher permission bound to
the clean commit and fixed scope. Policy records explicitly grant no authority.
Capture the phase clock before launcher I/O or native imports. Under the
permission, create bounded create-only launcher evidence that consumes the
attempt, then collect the native environment, form exact v1 development_go
attestation bytes in memory, and only afterward create the ArtifactStore root
and persist those same bytes. created_utc is attestation-formation time, not
proof of authorization. No wire-schema change is needed to claim pre-root order.

Pre-root failure preserves only bounded launcher evidence and any actual
partial root; it consumes the attempt. No alternate directory or automatic
retry. Missing/unavailable evidence stays explicitly unavailable. Retained
launcher metadata and any root copies count toward the same1-GiB cap; reserve
their bounded worst case inside the existing1-MiB shared failure allowance.
Runtime decisions stay outside the clean checkout while an attempt is active.

No claim of hostile-same-user provenance, hard preemption, power-loss recovery
or universal failure retention is introduced. Advisory locks and observed
file consistency are not substitutes for the fixed trusted runner and numerical
audit.

## API validation

Python documents nonblocking shared locks, descriptor-relative file operations
and explicit fsync. Linux locks are advisory and tied to open file descriptions;
a new reader descriptor must not be assumed to share a live writer's lock.
Read-only inspection must fail promptly on a held exclusive writer, or explicitly
use the writer's already-held descriptor within its trusted process. It must not
convert an existing lock or silently wait for a different process.

- [Python3.12 fcntl](https://docs.python.org/3.12/library/fcntl.html)
- [Python3.12 os](https://docs.python.org/3.12/library/os.html)
- [Linux flock](https://man7.org/linux/man-pages/man2/flock.2.html)

These documented interfaces support the implementation choices; they do not
prove the experiment's native correctness, runtime or storage feasibility.

NumPy's documented integer bounds/dtypes and explicit seeded Generator behavior
were checked against the actual iteration003/006 producer calls. The historical
`default_rng` spelling is retained; fixture tests compare its bytes with an
independent explicit `Generator(PCG64(SeedSequence(...)))` oracle. Environment
version binding remains required; this is not a cross-version distribution
compatibility claim.

- [NumPy Generator.integers](https://numpy.org/doc/stable/reference/random/generated/numpy.random.Generator.integers.html)
- [NumPy PCG64](https://numpy.org/doc/stable/reference/random/bit_generators/pcg64.html)
