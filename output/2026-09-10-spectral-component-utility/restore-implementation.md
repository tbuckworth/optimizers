`restore` is an explicit dictionary operation. It validates before construction,
builds the literal 784–256–128–10 FP32 model, loads independent copies, reconstructs
canonical ownership aliases and performs exact tree-value round-trip comparison.
Only `cpu` and explicitly indexed CUDA destinations such as `cuda:0` are accepted;
CUDA transfer is source-prepared but **not exercised or admitted here**.
`expected_step` is mandatory. The adapter permits canonical fabricated counts
0…56,305, including the single proposed post-final private step; the eventual
runner must bind actual parent selection to exactly 100 or 56,304.

The full ordered schema, six named parameter shapes/order, model specification,
gradient shapes/presence, all module modes, optimizer group keys/configuration,
ordered IDs, per-parameter FP32 scalar steps and finite first/second moments
are checked. Negative second moments are rejected. The native tracker must have
exactly the canonical attributes/settings, matching clock, compatible finite
FP32 basis/mean and CPU FP64 positive descending singular values, no adaptive
rank and bounded integer diagnostics. No I9 restoration or schema relabeling
is used. The implementation reuses only the unchanged canonical factories and
shape-agnostic clone/tree/ownership helpers.

## RNG and snapshot semantics

Construction uses CPU-only `fork_rng(devices=[])` and the CPU default generator,
not `torch.manual_seed`, which would also schedule accelerator seeding. Caller
Python/NumPy/CPU torch RNG is unchanged in success fixtures and constructor
failure fixtures.

The saved RNG is **validated and preserved as payload, not installed globally**.
Python and NumPy schemas and bounded values are checked and accepted by private
generators; the CPU torch state is accepted by a private CPU generator. Recorded
CUDA states are bounded dense CPU byte vectors, copied without CUDA inspection.
Their internal device-specific encoding is not semantically validated by these
CPU tests. `snapshot_with_rng` explicitly receives that validated recorded RNG;
it is not falsely advertised as a new capture of ambient RNG.

The round-trip check therefore verifies exact recorded state payload plus
restored model/Adam/tracker/gradient/mode values while keeping ambient RNG
isolated. It does not bypass RNG schema validation. Canonical forward/filter/
Adam actions have no random draws after panels/shifts are fixed, but the runner
still owns the pinned deterministic environment and real baseline-logit check.

`snapshot_with_rng` requires matching native observer and Adam clocks. A private
raw-bypass endpoint deliberately advances only Adam and must be recorded as an
endpoint/moment result, **not** relabeled as a canonical strong snapshot.

## Restricted explicit loading

The optional `load_snapshot` requires an absolute path, exact positive byte
size (maximum 256 MiB), exact SHA-256 and expected step. It opens a nonblocking,
non-leaf-symlink descriptor, checks a regular file and pinned size, hashes the
same descriptor before and after `torch.load(map_location="cpu", weights_only=True)`,
and verifies descriptor metadata through the final hash. It then validates the
complete snapshot dictionary. There is no fallback to broad pickle, safe-global
extension, implicit model restoration or automatic retry.

This is not a serialization sandbox: process memory/time limits, trusted source
provenance and exact manifest pinning remain necessary before an admitted load.
No actual parent file was read through this wrapper; its files were temporary
fabricated snapshots generated by the tests.

## Official-library validation and remaining boundaries

The best-practices-validator skill prompted checking versioned PyTorch 2.11
documentation before implementation. The design addresses these documented
behaviors:

- Optimizer state IDs are matched to live parameters by order without additional
  identity verification, so the adapter checks names/shapes/order/config explicitly.
  [AdamW state dictionaries](https://docs.pytorch.org/docs/2.11/generated/torch.optim.AdamW.html#torch.optim.AdamW.state_dict).
- CPU RNG is always included in `fork_rng`; an explicit empty device list avoids
  selecting accelerator generators.
  [Random-state APIs](https://docs.pytorch.org/docs/2.11/random.html#torch.random.fork_rng).
- Explicit CPU mapping and restricted loading avoid implicit accelerator storage
  loading and permissive pickle fallback, but are not a complete security boundary.
  [torch.load](https://docs.pytorch.org/docs/2.11/generated/torch.load.html).

Real checkpoint compatibility, GPU device mapping/round-trip behavior, source
baseline logits, action-time environment fidelity, full-rank memory/runtime
and the complete acquisition/audit envelope remain unverified and unadmitted.
The wrapper does not validate the complete historical observer trajectory or
turn these source checks into an independent training replication.
