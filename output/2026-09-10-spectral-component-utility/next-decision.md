# Next decision: assess familiarity versus frequency, without launching a study

Codex — Spectral Optimizer Investigation · 10 September 2026

**GO for a bounded design assessment. No acquisition selected.** The user's
augmentation priority, signed-component diagnostic, reviewed HTML report and
paper integration are complete. This resumes a question already present in
the approved safety-first plan, not a new language-model or speed objective.

## Why this question is next

The current evidence contains useful protection, restricted rare correct
learning and a conditional observer-history pathway. It does not distinguish
being low-frequency during continuation from being absent/unlearned before
the observer and model history formed. The component diagnostic did not
establish a universal consistency explanation. Repeating its two saved stages
or adding another local dot-product table would not answer this distinction.

The constructive possibility is meaningful: a policy may preserve learned rare
competence while admitting new useful information in some familiar geometries.
The adverse possibility is also meaningful: it may obstruct correct learning
regardless of familiarity. Neither result is presumed. This design is not a
gate before reporting the already demonstrated useful learning.

## Bounded deliverable before any new code or compute

Assess a small counterbalanced familiarity×continuation-frequency comparison
using the existing small MNIST implementation. Rotate which true digit group
is designated rare, keep labels correct for that group, and pair raw/native
continuations on the exact same indexed examples within each cell. Separate
retention of competence actually acquired in warmup from subsequent useful
progress, with common and rare outcomes visible at the phase boundary and
fixed endpoint. A low-frequency effect without useful warmup competence cannot
answer a preservation question.

The assessment must specify how warmup exposure is replaced, equal update and
optimizer clocks, which full state changes with familiarity, and what remains
coupled. Frequency necessarily changes group exposure across frequency cells;
do not claim equal exposure across that factor. Familiarity changes model and
optimizer/observer history, so a learning-level factorial alone will not isolate
pure observer memory. Determine whether the expected informational gain is
worth a genuinely new study after these qualifications, and retain a no-go
option if it duplicates completed evidence.

Read existing selectivity/batching/observer protocols and actual source/state
availability. Produce one concise design/estimand assessment and, only if
warranted, a proposed fixed minimal protocol/resource estimate. No real model
load, smoke run, new training, source mutation, paid reservation or use of
missing intermediate states is admitted by this design decision. Subsequent
implementation/admission remains autonomous under existing user authority;
this is not a request for another user approval.
