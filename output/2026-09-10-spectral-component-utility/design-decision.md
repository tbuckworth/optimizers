## Why this adds understanding

The prior study established useful native post-warmup learning and an adverse
native-plus-translation combination. It did not establish which objective
changes accompany a native rather than raw action at the *same* model and
inherited Adam/observer state. The earlier direction/size and energy diagnostic
did not measure signed softened-target (S), realized-label (F) and exact
view-consistency (C) changes. Their sum accounts for augmented assigned-label
CE, not the causes of separate clean performance.

The [independent mathematical assessment](design-math.md), main
first-principles check (artifact not distributed in this public snapshot) and [design review](design-review.md)
support this distinct question. A constructive outcome remains possible:
reduced realization fitting while useful clean progress survives. Reduced
consistency and clean progress, lost softened-target progress, extra realization
fitting, mixed seeds or effects below numerical resolution also remain possible.
The algebra fixes none of those signs. No outcome is assumed.

## What is selected

The [protocol](protocol.md) fixes twelve existing native parents: three seeds,
unaugmented/translated training, warmup/final. Two identical translated action
batches per seed feed raw and native private branches at each parent. Each
branch takes exactly one inherited-state action and is then discarded. The
original parent is never advanced. Exact 25-shift evaluation separates S/F/C;
separate original-image clean CE is primary competence. The primary paired
contrasts are final translated-parent clean-CE and C changes, with all three
seed results shown. All other registered cells and readouts remain visible.

The [source inventory](source-inventory.md) establishes that these snapshots
exist but intermediate restorable models do not. Their schema/model differ
from the old I9 restore helper; a new strict adapter is necessary. All fifteen
original scientific source hashes match the completed producer pins. No
scientific checkpoint or array has been opened for this new study.

## Review findings resolved in the design

1. Accuracy/CE reductions now explicitly distinguish original-image and
   equally weighted per-view outcomes. Mean-logit objectives cannot silently
   replace either. Original-image actually-wrong-subset fit is primary for
   that proxy; mean-per-view fit is secondary.
2. Derivative dots use each materialized FP32 path point's actual displacement,
   subtracted in FP64. Finite data-only comparisons use the decay path at the
   same fraction. A 0.1 path is not an additional optimizer update.
3. Parent rows are explicitly sorted by seed and none/translate, with warmup
   before final. Inventory (artifact not distributed in this public snapshot) now binds all six original
   plan receipts and all twelve corresponding readout receipts as well as
   checkpoint receipts. Future source checks must enforce their relationship,
   byte integrity, exact reporting role and producer batching semantics.

The independent review is preserved as written, including its pre-amendment
input hashes. Main owns these explicit resolutions; it does not relabel the
review as an audit of source that had not yet been written.

## Boundaries and next work

This is outcome-informed reuse of existing trained states/reporting data,
not fresh efficacy confirmation. A common-parent action can establish a local
intervention effect; co-occurring component and clean changes do not identify
mediation of the full-trajectory gap. Unaugmented parents receive hypothetical
onset-of-augmentation actions. No new training, component-Adam arms, rank/LR
sweep, size-matching extension, paid run or broad speed benchmark is selected.

Proceed with new import-inert objective and strict restore helpers plus
fabricated CPU tests. Main will read/review their complete source and results.
Then prepare the fixed runner and independent saved-array audit, exact output
and live-object memory bounds, committed input/source freeze and one bounded
local resource admission. No real-data smoke test precedes that admission.
Limits remain the protocol's 8 GiB archive, 8 GiB host, 4 GiB GPU and fixed
deadlines; feasibility estimates are not permission to retry or shrink a run.
